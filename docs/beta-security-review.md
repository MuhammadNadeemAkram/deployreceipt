# Task 06 security review and risk register

Review scope: main including merged Task05, Auth/actions/proxy, all eight prior migrations, RLS/grants, review snapshots/evidence, PDF and isolated worker. This is an engineering review, not penetration-test certification. Current deployment status: **blocked by configuration**, not ready for production launch.

## Findings resolved in code

| Severity | Finding and impact                                                                                    | Resolution / verification                                                                                                                                               |
| -------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High     | Public registration and no environment-wide admission gate allowed unrestricted account creation      | Closed public onboarding; operator email allowlist, Auth hook, verified active-session checks and restrictive RLS on all app tables/Storage; DB and real workflow tests |
| High     | Revoked JWT could otherwise read until token expiry; web Auth lookup alone did not prove live session | Match JWT session_id to current auth.sessions and confirmation/admission on every protected DB statement; real sign-out and stale JWT denial tests                      |

| Medium   | Missing abuse controls on project/report/review/comment writes                                        | Atomic DB windows, per-actor advisory lock and total project cap; existing scan/PDF quotas retained                                                                     |
| Medium   | Default cookies/script policy and missing correlation made operational controls weaker                | HttpOnly/Secure hosted/Lax cookies, per-response nonce CSP, defensive headers, private cache control and generated IDs                                                  |
| Medium   | No worker heartbeat/readiness or DB lease pause                                                       | Private heartbeat/queue RPCs, bounded health files and lease wrapper kill switch; no secret-bearing public health                                                       |
| Medium   | PDF8 MiB exceeded Vercel response budget; bucket accepted5 MiB vs worker2 MiB                         | PDF4 MiB cap and bucket2 MiB, existing PNG/worker/thread/page/time bounds retained                                                                                      |
| Low      | Release list fetched entire frozen reports                                                            | Summary-only projection, additional operational/join indexes; bounded local measurements in CI proof                                                                    |

Review approvals preserve version-bound digests, immutable original observations/decisions/events, admitted verified-email identity, expiry/revocation, optimistic/concurrent replay rejection and cross-project denial. Existing real release workflow tests remain mandatory. CSRF uses Server Action origin checks plus explicit API origin checks; routes do not trust submitted owner IDs. PDF uses local font/PNG bytes in a bounded Node worker, no HTML/browser/external resources. Storage access requires admitted authorized identity and retention; no public bucket or permanent signed-URL evidence.
